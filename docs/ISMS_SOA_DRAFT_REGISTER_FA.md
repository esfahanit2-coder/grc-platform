# پیاده‌سازی دفتر تصمیم‌های کنترلی SoA — مرحله B1، Issue #143

**وضعیت: قابل استفاده فقط برای جمع‌آوری و اصلاح پیش‌نویس کنترل‌ها؛ نه بیانیه کاربردپذیری تأییدشده.**

این مرحله مدل‌های `SoARegister` و `SoAControlDecision` و API محدود ایجاد/خواندن/ویرایش را در برنامه `apps.reporting` به پلتفرم اضافه می‌کند؛ بدون بازنویسی موتور Framework، Risk و Control.

## مسیرهای API

- `GET /api/v1/soa/registers/` — فقط پرونده‌های مجاز کاربر بر اساس Tenant و محدوده واحد سازمانی.
- `POST /api/v1/soa/registers/` — ایجاد پرونده پیش‌نویس برای **FrameworkVersion قفل‌شده متعلق به Tenant**.
- `GET /api/v1/soa/registers/{uuid}/` — جزئیات و تصمیم‌های ثبت‌شده با وضعیت صریح Draft.
- `POST /api/v1/soa/registers/{uuid}/decisions/` — ثبت تصمیم برای Control قابل مشاهده همان Tenant.
- `PATCH /api/v1/soa/registers/{uuid}/decisions/{uuid}/` — فقط تغییر تصمیم، توجیه، اتصال پیاده‌سازی و درمان ریسک؛ کد مرجع و شناسه Control تغییرناپذیرند.

دو نوع موجودیت `soa_register` و `soa_decision` در `Domain Object Registry` مرکزی اضافه شده‌اند؛ اولی تنها امکان ارتباط با سند را دارد و دومی امکان ارجاع شواهد و سند را، با کنترل Tenant و `register.organization_unit`. این ثبت **منشأ خودکار اثبات انطباق ایجاد نمی‌کند**؛ ارزیابی ارزش شواهد و تأیید مستقل در B2 لازم است.

خواندن به `report.view` و محدودیت سازمانی موجود وابسته است؛ نوشتن فعلاً محافظه‌کارانه به مجوز **whole-tenant `report.generate`** نیاز دارد. هیچ endpoint برای `approved`، صدور گواهی یا SoA نهایی وجود ندارد. API قدیمی `type=soa` مستقل باقی می‌ماند و برچسب Draft آن همچنان معتبر است.

## مدل اطلاعات مرحله B1

`SoARegister`: Tenant، واحد سازمانی، نسخه Framework قفل‌شده، عنوان، شماره بازنگری، ایجادکننده، وضعیت ثابت `draft`؛ قید یکتایی Tenant + واحد + نسخه + بازنگری.

`SoAControlDecision`: Control، نوع مرجع (`annex_a` یا `additional`)، شناسه مرجع تأییدنشده، انتخاب (`undecided`، `included`، `excluded`)، توجیه کارشناس، پیوند اختیاری ControlImplementation و RiskTreatment و آخرین ویرایشگر. تکرار کنترل یا شناسه در یک دفتر مردود است. اتصال Implementation فقط به همان Control و واحد و Tenant مجاز است؛ Treatment فقط با ریسک متعلق به Tenant و واحد یکسان **و با رابطه موجود RiskControl به همان ControlImplementation** مجاز است؛ پیوند درمان بدون این رابطه رد می‌شود. **پیوند به Treatment به‌تنهایی اثبات انتخاب یا اثربخشی کنترل نیست.**

توجیه برای هر تصمیم include/exclude اجباری است و یک کنترل مستثنی نباید به‌عنوان کنترل پیاده‌شده یا درمان‌شده در همان تصمیم ثبت شود. هیچ شناسه عددی کاربر، بدون تطبیق منبع انسانی، به‌عنوان Control Annex A معتبر یا دارای حق نشر تعبیر نمی‌شود.

## مرزهای استاندارد و حقوق استفاده

- نمایه عددی ISO 27001/27002 می‌تواند فقط نقش راهنمای ساختاری داشته باشد؛ متن اصلی محافظت‌شده از PDF به GitHub عمومی منتقل نمی‌شود.
- B1 اعتبار کلی ۹۳ شناسه، پوشش همه کنترل‌های مرجع، صحت crosswalk، الزامات اضافه سازمانی، صلاحیت امضاکننده یا صورت‌وضعیت پیاده‌سازی را **احراز نمی‌کند**.
- درخواست POST اجازه تنظیم `status=approved` و داده‌های خارج از قرارداد را نمی‌دهد. فیلد `is_formal_statement_of_applicability=false` در خروجی‌ها ثابت است.
- نسخه‌های مشتری یا داده حساس را در CI عمومی نفرستید. تست‌های GitHub فقط ساختار و اطلاعات ساختگی را آزمایش می‌کنند.

## باقی‌مانده مرحله B2 و Gate مشتری

تکمیل اعتبارسنجی منبع و رابطه نسخه واقعی ISO/AFTA، بررسی ۹۳ تصمیم مرجع، دلایل تفصیلی شامل/مستثنا، شواهد قابل ممیزی، پیوند RTP مصوب، نقش بازبین مستقل، snapshot/approval نسخه تغییرناپذیر و خروجی رسمی قابل امضا به PRهای بعدی نیاز دارد. تا آن زمان #143 و #5 باز بمانند. قبل از ادعای آمادگی نصب/فروش نیز آزمون نصب روی Host تمیز، بازیابی، نفوذ و UAT بر اساس #68 و #74 ضروری‌اند.

## حفاظت از مسیر خروجی قدیمی Word

مسیر قدیمی `GET /api/v1/reports/soa/{assessment_id}/` در `apps.documents.exporters.soa_docx` نیز بازبینی شد. خروجی جدید صریحاً Draft/Not Approved است. نگاشت `ControlRequirement` به معنی `Applicable=Yes` نیست؛ کاربردپذیری `Undetermined` و اعتبار مدارک `Not verified` درج می‌شود. کوئری با **Tenant نگاشت و مالکیت Control** محدود شده تا نگاشت به Framework مشترک نتواند عنوان کنترل دیگر مشتری را افشا کند. آزمون واقعی، یک نگاشت عمداً ناسازگار بین دو Tenant ایجاد می‌کند و عدم افشای آن در فایل Word را بررسی می‌کند. این خروجی **هنوز SoA واقعی نیست** و نباید با گزارش رسمی یا تأییدیه اشتباه شود.
