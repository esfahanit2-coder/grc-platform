# سخت‌سازی تشخیص تغییرات پرونده SoA هنگام بازبینی — Issue #153

این تغییر فقط **بازبینی انسانی پیش‌نویس** را ایمن‌تر می‌کند و هیچ امکان تصویب، امضا، تأیید انطباق، حقوق انتشار استاندارد یا تحویل عملیاتی ایجاد نمی‌کند.

## اشکال شناسایی‌شده در نسخه اولیه M1

پس از ادغام PR #152، اثرانگشت داخلی درخواست بازبینی، شناسه پیاده‌سازی کنترل یا درمان ریسک را لحاظ می‌کرد اما تغییر وضعیت واقعی پیاده‌سازی، اثربخشی کنترل، تصویب درمان ریسک، نوع ارتباط RiskControl و بعضی تغییرات محتوایی Evidence را به‌طور صریح محاسبه نمی‌کرد. در نتیجه بدون عوض‌شدن شناسه پیوند، ممکن بود درخواست قبلی «بدون تغییر» نمایش داده شود.

## اصلاح

تابع `draft_review_digest` اکنون علاوه بر موارد سابق، وضعیت و هویت کنترل‌های مرجع، وضعیت و اثربخشی و واحد پیاده‌سازی، وضعیت و مصوبه درمان ریسک، ارتباط واقعی RiskControl، و برخی اطلاعات ساختاری و محتوایی شاهد را در اثرانگشت داخلی وارد می‌کند. متن شاهد یا متن کنترل‌های دارای مجوز در خروجی API ظاهر نمی‌شود؛ صرفاً هش داخلی به‌صورت خصوصی نگهداری می‌شود و API فقط `snapshot_stale` و `can_respond` را گزارش می‌کند.

هرگاه وضعیت مرتبط حتی با `QuerySet.update()` بدون تغییر `updated_at` عوض شود، پاسخ به درخواست قبلی باید با HTTP 409 متوقف شود. برای ادامه بازبینی باید دور جدید ثبت شود و تاریخچه دور قبلی حفظ گردد.

در مسیرهای عادی `POST/PATCH` تصمیم‌های SoA نیز قفل تراکنشی `select_for_update` روی همان ردیف SoARegister اخذ می‌شود که درخواست و پاسخ بازبینی از آن استفاده می‌کنند. بدین ترتیب درخواست‌های همزمان ویرایش تصمیم و بازبینی از مسیرهای API نرم‌افزار به‌صورت ترتیبی انجام می‌شوند.

## آزمایش‌ها

- تغییر وضعیت پیاده‌سازی و اثربخشی کنترل بدون تغییر timestamp باعث stale و رد پاسخ می‌شود.
- تغییر approval_status درمان ریسک و سپس نوع رابطه RiskControl باعث stale و 409 می‌شود.
- تغییر مستقیم text_content شاهد لینک‌شده بدون تغییر timestamp نیز باعث stale و 409 می‌شود و متن محرمانه جدید افشا نمی‌شود.
- همه این موارد مستقل از «تأیید SoA» هستند؛ `SoARegister.status=draft` می‌ماند.
- تست‌های جامع، اسکن امنیت و شبیه‌سازی مهاجرت موجود باید روی SHA دقیق PR موفق شوند و پس از ادغام دوباره روی main سنجیده شوند.

## محدودیت و مرز ایمنی

این Fingerprint امضای الکترونیکی رسمی، اعتبار قانونی منبع، ضمانت تغییرناپذیری فایل ذخیره‌شده بیرونی یا Snapshot اتمیک تمام سامانه‌های متصل نیست. مسیرهای مدیریتی خارج از ORM و API، فایل‌های درون ذخیره‌ساز و وقایع خارجی نیازمند کنترل جداگانه‌اند. همچنین وجود ۹۳ شناسه Annex A و یکپارچگی Checksum داخلی **به‌هیچ‌وجه تأیید انطباق یا ضرورت انتخاب همه کنترل‌ها نیست**.

اجرای واقعی SoA مصوب همچنان منوط به مستندات مجاز استاندارد، کفایت شواهد/RTP، تأییدکننده مستقل، نسخه تغییرناپذیر و UAT/نصب/بازیابی مشتری است. Issueهای #5، #68، #74، #143 و #151 باز باقی می‌مانند.
