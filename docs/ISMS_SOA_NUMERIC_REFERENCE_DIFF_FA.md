# مقایسه عددی شناسه‌های کنترل Annex A — مرحله B2b، Issue #143

**نوع خروجی:** مقایسه ساختاری شناسه‌های عددی، نه محتوای ISO/IEC، نه اعتبارسنجی حق نشر، نه بررسی انتخاب کنترل سازمان، و نه تأیید انطباق.

## هدف

در سند مرجع ساختاری عمومی و بدون متن دارای حق نشر، ۹۳ شناسه کنترلی Annex A برای ISO/IEC 27001:2022 وجود دارد: گروه ۵ شامل ۳۷، گروه ۶ شامل ۸، گروه ۷ شامل ۱۴ و گروه ۸ شامل ۳۴ شناسه. این اعداد با نمایه غیرقابل‌واردکردن `content-packs/references/iso-iec-27001-2022-structure-only.json` تطبیق داده شده‌اند. خود JSON صرفاً شناسه و مشخصات منشأ PDF را دارد و **مجوز انتشار متن استاندارد یا نتیجه ارزیابی نیست**.

## API (کاملاً فقط‌خواندنی)

`GET /api/v1/soa/registers/{uuid}/reference-diff/?reference=iso-iec-27001-2022-annex-a-structure-only`

پارامتر `reference` باید **صریحاً** ارسال شود؛ نرم‌افزار از عنوان چارچوب دلخواه حدس نمی‌زند که استاندارد ISO است. ابتدا Tenant و محدوده واحد سازمانی مطابق `report.view` کنترل می‌شود. هیچ حالت ایجاد/ویرایش/تأیید/امضا وجود ندارد. همچنین این API در پرونده‌های چارچوب غیرمرتبط صرفاً یک آزمایش مقایسه شناسه انجام می‌دهد و درباره هویت منبع آن پرونده اظهار نظر نمی‌کند.

## معنا و محدودیت اعداد

- `matched_numeric_identifiers`: تعداد شناسه‌های دقیقا منطبق با نمایه عددی، صرف‌نظر از انتخاب یا استثنا. یک کنترل مستثنا همچنان می‌تواند **تصمیم ثبت‌شده** باشد؛ قرار نیست همه کنترل‌های Annex A برای هر سازمان انتخاب شوند.
- `missing_numeric_ids`: شناسه‌های مرجع که برای آن‌ها هنوز تصمیمی در این دفتر ثبت نشده است.
- `unrecognized_annex_a_ids`: شناسه‌های ثبت‌شده با نوع `annex_a` که با ساختار عددی نسخه مقایسه تطابق دقیق ندارند. نرم‌افزار آن‌ها را به‌طور خودکار اصلاح یا به نسخه دیگر نگاشت نمی‌کند.
- `undecided_numeric_ids`: مواردی که سطر تصمیم دارند ولی تصمیمشان `undecided` است.
- `additional_organizational_control_decisions`: تعداد کنترل‌های اضافه سازمانی، بدون الزام عددی Annex A.

حتی اگر ۹۳ شناسه منطبق و هیچ شناسه مفقودی وجود نداشته باشد، **هیچ اثباتی** درباره قانونی‌بودن استفاده از متن، کفایت محتوای کنترل، ضرورت انتخاب آن کنترل، کیفیت شواهد، درست‌بودن RTP یا تأیید شخص صاحب اختیار به دست نمی‌آید. خروجی همیشه `formal_attestation_allowed=false`، `framework_source_identity=not_verified` و `source_rights_review=not_verified` دارد. شناسه‌های فاقد تطبیق و تصمیم‌های نامشخص باز هستند و باید انسانی بازبینی شوند.

## پذیرش و امنیت

آزمون‌ها باید پارامتر مقایسه اجباری، مجموع ۹۳ شناسه و مرزهای ۳۷/۸/۱۴/۳۴، دفتر خالی، included و excluded و undecided، کنترل سازمانی اضافه، شناسه ناشناخته، دسترسی واحد دیگر، Tenant دیگر و ممنوعیت POST را پوشش دهند. همچنین هیچ متن استاندارد، عنوان کنترل یا محتوای حساس مشتری دیگری در خروجی نشت نکند.

## کارهای باز

این ابزار برای آماده‌سازی مسیر رسمی B2 است؛ محتوای دارای مجوز باید **خصوصی و با اختیار قانونی** وارد شود، نگاشت شناسه به کنترل و پیوندهای ریسک/شاهد را بازبین متخصص تأیید کند، مسیر تصویب با امضاکننده مستقل و snapshot تغییرناپذیر ساخته شود و UAT واقعی اجرا گردد. Issueهای #143، #5، #68 و #74 تا تحقق معیارهای واقعی باز می‌مانند.
