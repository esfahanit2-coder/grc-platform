# راهنمای محیط فارسی پیش‌نویس SoA — رابط کاربری اولیه، Issue #143

**هشدار حقوقی و محصولی:** صفحات `/soa` و `/soa/{id}` تنها برای ثبت و ارزیابی پیش‌نویس تصمیم‌های کنترل هستند. هیچ دکمه، API یا خروجی «تصویب، امضای رسمی، صدور گواهی، انتشار SoA یا اعلام انطباق» در این بخش وجود ندارد. وضعیت ثابت `DRAFT / NOT APPROVED` از Backend می‌آید و در صفحات آشکار نشان داده می‌شود. PDFهای حفاظت‌شده ISO/AFTA/CIS وارد ریپازیتوری عمومی نشده‌اند.

## امکانات

- فهرست `/soa`: نمایش پرونده‌هایی که کاربر مجوز مشاهده آنها را در Tenant و واحد سازمانی مربوطه دارد. ایجاد پیش‌نویس فقط با انتخاب واحد و نسخه **قفل‌شده و متعلق به Tenant**؛ کنترل نهایی نسخه، مالکیت و مجوز `report.generate` بر عهده Backend است.
- صفحه `/soa/{id}`: دریافت جزئیات و تصمیم‌های واقعی و نمایش کدهای نقص از `GET /soa/registers/{id}/readiness/`، همراه با موانع دائمی «عدم تأیید پوشش منبع، حقوق محتوا و امضای انسانی».
- ثبت و ویرایش تصمیم: انتخاب کنترل، نوع مرجع Annex A یا کنترل اضافه سازمان، کد مرجع، وضعیت انتخاب/استثنا/نامشخص و دلیل انسانی. شناسه و کنترل هنگام ویرایش تغییر نمی‌کنند. انتخاب پیوند اختیاری پیاده‌سازی و درمان ریسک با شرط تطابق رابطه `RiskControl` در Backend اعتبارسنجی می‌شود.
- اگر کاربر دسترسی مشاهده اطلاعات اختیاری ریسک/پیاده‌سازی را نداشته باشد، می‌تواند تصمیم ساده را **بدون پیوندهای اختیاری** ثبت کند؛ سرور همه محدودیت‌های Tenant و واحد و Control را راستی‌آزمایی می‌کند.
- لینک مسیر در منوی اصلی و مرکز گزارش‌ها؛ گزارش قدیمی `type=soa` صریحاً با برچسب «کاربرگ پیش‌نویس کاربردپذیری (تأییدنشده)» نمایش داده می‌شود و متن `notice` صادرشده توسط API در پیش‌نمایش نشان داده می‌شود.

## معیار آزمایش دستی پس از عبور از CI

۱. با کاربر Admin برای Tenant الف، حداقل یک چارچوب اختصاصی قفل‌شده و واحد مجاز انتخاب و پیش‌نویس ایجاد کنید. ایجاد برای نسخه آزاد یا سراسری باید رد شود.

۲. با کاربر دارای `report.view` فقط برای واحد A، فهرست و جزئیات A مشاهده می‌شود اما B یا Tenant دیگر نباید قابل مشاهده باشد. اگر مجوز `report.generate` ندارد، ثبت تصمیم باید با پاسخ 403 متوقف شود و پیام مناسب نمایش داده شود.

۳. تصمیم included بدون دلیل باید رد شود؛ درمان ریسک نامرتبط باید رد شود؛ برای excluded پیوند اجرا و درمان نباید ارسال شود. امکان ثبت `undecided` وجود دارد، ولی در readiness نقص نشان داده می‌شود.

۴. شاهد منقضی‌شده یا مربوط به واحد دیگر نباید به عنوان شاهد معتبر اولیه حساب شود. حتی با صفر نقص ردیفی، `register_findings` و `formal_attestation_allowed=false` دیده شوند.

۵. فهرست می‌تواند در API تا ۲۰۰ رکورد نمایش دهد. این **محدودیت موجود API** است؛ برای استفاده گسترده نیاز به صفحه‌بندی واقعی و فیلترهای سروری داریم. فهرست‌های مرجع UI نیز اکنون تا ۲۰۰ رکورد درخواست می‌کنند؛ در سازمان‌های پرموجودیت به صفحه‌بندی و جستجوی سروری نیاز است.

۶. در `/reports` عنوان و متن پیش‌نمایش سابق SoA هرگز با ادعای «تأیید رسمی» ارائه نشود. سایر گزارش‌ها نباید تحت تأثیر تغییر عنوان قرار بگیرند.

## شروط ادامه B2

- تکمیل گواهی حقوق محتوا و شناسه‌های مرجعِ مورد تأیید مشتری؛ تطبیق کنترل‌های لازم به نحوی که وجود همه ۹۳ شناسه مرجع برابر با «همه کنترل‌ها الزامی‌اند» تفسیر نشود.
- بررسی تخصصی کفایت مدارک و RTP، نقش بازبین و امضاکننده مستقل، قفل نسخه نهایی، تغییرناپذیری Snapshot تصویب‌شده، حفظ سوابق، خروجی رسمی قابل استناد؛ نه فقط برچسب‌های UI.
- اجرای UAT مشتری، نصب و بازیابی تمیز، آزمون نفوذ، مدیریت صلاحیت‌های بهره‌برداری؛ Issueهای #5، #68، #74 و #143 همچنان باز خواهند ماند.
